# 리드문 작성 스킬 (유사도 기반 few-shot)

제안서의 핵심 리드문을 **일괄 생성**하는 도우미입니다.
한 줄씩 쓰지 않고, 전체 구조를 파악한 뒤 한 번에 출력합니다.

**핵심 원리**: 매 슬라이드마다 기존 제안서 코퍼스(1,900+ 리드문)에서
**가장 유사한 예시를 검색(retrieval)**해 few-shot으로 참고하고,
작성 후 **규칙 채점기로 self-check**합니다. 이 과정은 전부 로컬 계산이라
**Anthropic API를 호출하지 않습니다** — 생성은 이 스킬을 실행하는 Claude가 직접 합니다.

## 워크플로우

```
Phase 1: 설정 → Phase 2: 검색+호흡 맞추기 → Phase 3: 검색 기반 일괄 생성 → Phase 4: 인간 수정
```

---

## Phase 1: 설정

사용자에게 다음 정보를 요청합니다.

### 1-1. 기본 정보
```
제안서 리드문 일괄 생성을 도와드릴게요!

먼저 기본 정보를 알려주세요:

1. **산업/분야**: (예: 환경, 사회서비스, 핀테크, 헬스케어...)
2. **참고 자료**: (기존 PPT, 회의록, 소개서 등 - 없으면 "없음")
```

### 1-2. 슬롯 값 정의
리드문은 슬롯(변수)을 실제 값으로 채워 완성합니다. 값을 먼저 확정합니다.
```
다음 변수들의 값을 알려주세요:

• ORG (수행사): MYSC
• PARTNER (발주처/협력기관): 중앙사회서비스원
• TARGET (대상): 사회서비스 스타트업
• METHOD (방법): 액셀러레이팅
• EFFECT (효과/목표): 투자 유치 활성화
• 기타 필요한 변수...
```

### 1-3. 파트 구성
검색은 **파트(PART)** 단위로 이뤄지므로, 각 섹션을 아래 파트에 매핑합니다.

| 파트 | 의미 |
|------|------|
| `INTRO` | 제안사 소개 |
| `OVERVIEW` | 사업 개요 |
| `PART_1` ~ `PART_4` | 상세 내용 (본론) |
| `PLAN` | 수행 계획 |
| `UNKNOWN` | 분류 애매 (fallback) |

```
제안서 구조를 알려주세요. 예:
- INTRO (제안사 소개): 2장
- OVERVIEW (사업 개요): 3장
- PART_1 (핵심 전략): 8장
- PLAN (수행 계획): 4장

총 17장
```

## Phase 2: 검색 + 호흡 맞추기

2-3개 샘플을 **검색 기반으로** 먼저 생성해 톤을 조율합니다.

각 샘플 슬라이드마다:

1. **파트/슬롯/키워드 판별** (Claude가 슬라이드 컨텍스트를 보고 결정)
   - `part`: 위 표에서 하나
   - `slots`: 이 리드에 넣을 슬롯 (예: `ORG,TARGET,METHOD`)
   - `keywords`: 슬라이드 핵심 키워드 2-4개 (예: `환경,스타트업,성장`)

2. **유사 예시 검색** — 아래 명령으로 few-shot 예시를 받습니다.
   ```bash
   python3 lead_retriever.py --part PART_1 --slots ORG,TARGET,METHOD \
       --keywords 환경,스타트업,성장 --k 5 --json
   ```
   - 반환: `output`(슬롯 템플릿 리드문), `score`, `keywords`, `bucket`, `similarity`
   - 어떤 슬롯 조합이 있는지 모를 땐: `python3 lead_retriever.py --part PART_1 --list-buckets`

3. **작성** — 검색된 예시의 **문형/전개 방식을 참고**하되, 슬롯은 **Phase 1의 실제 값으로 치환**해 새 문장을 씁니다. (예시의 `{TARGET}` → "사회서비스 스타트업")

```
샘플 리드문을 생성했습니다. 이 톤이 맞나요?

[샘플 1 - INTRO]  (참고 예시 bucket: INTRO, sim 0.68)
"MYSC는 다양한 파트너와의 집합적 임팩트를 통해 창업 소셜벤처가
죽음의 계곡을 안정적으로 넘을 수 있도록 체계적으로 지원합니다."

피드백:
- [ ] OK, 이 톤으로 진행
- [ ] 더 간결하게 / 더 풍부하게
- [ ] 기타 (직접 입력)
```

## Phase 3: 검색 기반 일괄 생성

확정된 스타일로 **모든 슬라이드**에 대해 아래를 반복합니다.

1. 파트/슬롯/키워드 판별
2. `lead_retriever.py`로 유사 예시 `--k 5` 검색
3. 예시를 few-shot으로 참고해 리드문 작성 (슬롯 = 실제 값 치환, 아래 제약 준수)
4. **best-of-N**: 후보를 2개 써서 self-check 점수가 높은 쪽 선택
5. **self-check**: 규칙 채점기로 하드 제약 검증
   ```bash
   python3 -c "from lead_scorer import score_lead; \
     print(score_lead('작성한 리드문', {'length_min':100,'length_max':120}))"
   ```
   - 반환된 `details`에서 `length_ok`, `ending_ok`, `comma`, `newline`, `multi_sentence`,
     `forbidden_words` 를 확인. **위반이 있으면 그 항목을 고쳐 재작성** 후 다시 채점.
   - ⚠️ 최종 리드문은 슬롯이 **실제 값으로 치환된 상태**이므로 `missing_slots` /
     `unknown_placeholders` 항목은 무시합니다(그건 템플릿 검증용). 숫자(연도·금액 등)가
     들어가 `digit_leak`이 떠도 실제 값이면 정상입니다.

전체가 통과하면 한 번에 출력합니다.

```
=== 전체 리드문 (17장) ===

[1] INTRO - 제안사 소개  (bucket: INTRO)
"MYSC는 다양한 파트너와의 집합적 임팩트를 통해 창업 소셜벤처가
죽음의 계곡을 안정적으로 넘을 수 있도록 체계적으로 지원합니다."

[2] OVERVIEW - 사업 목표  (bucket: OVERVIEW__METHOD-TARGET)
"본 사업은 중앙사회서비스원과 협력하여 사회서비스 스타트업의 역량을
강화하고 투자 유치를 활성화하는 지속 가능한 성장 기반을 마련합니다."

...

===
위 내용을 복사해 사용하시고, 필요한 부분만 수정해주세요!
```

## 리드문 제약 조건 (필수)

리드문은 **아이디에이션 제공**이 목표입니다. 풍부한 내용을 2-3문장으로 구성합니다.

| 항목 | 조건 | 비고 |
|------|------|------|
| 길이 | **100-120자** (필수) | 충분한 내용 전달 |
| 문장 수 | **2-3문장** 구성 | 단문 금지 |
| 엔딩 | "합니다.", "입니다.", "했습니다." 등 | 경어체 |
| 구성 | 핵심 주장 + 뒷받침 내용 | 논리적 전개 |
| 개행 | 사용 금지 (한 줄) | 필수 |
| 쉼표 | 최소화 | 채점 페널티 |
| 금지어 | "펠로우"→"펠로", "기업가 정신"→"임팩트 앙트프러너십" | 필수 |

**원칙**: 단순 요약이 아닌 **아이디에이션 제공**. 검색된 예시의 문형을 빌리되,
사용자의 실제 슬롯 값과 키워드로 구체화합니다.

## 검색기 참고 (lead_retriever.py)

- **입력 신호**: `part` + `slots` + `keywords`. 셋 다 정확할수록 유사도가 올라갑니다.
- **슬롯/키워드가 애매하면** 우선 `part`만으로 검색해도 됩니다(품질 점수 상위가 반환됨).
- **결과가 비면**: 해당 파트에 데이터가 없는 경우입니다. `--part UNKNOWN`으로 재시도하거나
  슬롯을 줄여보세요.
- **`similarity`** 는 슬롯 겹침(0.35) + 키워드 겹침(0.30) + 본문 키워드 등장(0.15) +
  코퍼스 품질점수(0.20)의 가중합입니다. 근사 중복 예시는 자동 제거되어 다양한 문형이 나옵니다.

## 참고 데이터 활용

사용자가 참고 자료(기존 제안서 등)를 제공하면:
1. 문체·용어·고유 표현을 추출해 작성에 반영
2. 코퍼스 검색 결과와 함께 few-shot으로 활용

참고 자료가 없으면 `learning_data/skill_examples/` 코퍼스 검색만으로 진행합니다.
